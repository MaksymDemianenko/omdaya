# Розгортання сайту (деплой)

Сайт — це Node.js-сервер (не статичні файли), тому потрібен хостинг, який вміє запускати Node.js
і має **постійне сховище (persistent disk)** для файлу `data.sqlite` — інакше вся база (тексти,
історії, FAQ і т.д., додані через адмінку) буде зникати після кожного перезапуску сервера.

Нижче — три варіанти, від найпростішого до повного контролю.

---

## Варіант 1 — Render.com (найпростіше)

У проєкті вже є готовий файл `render.yaml`.

1. Створіть акаунт на [render.com](https://render.com), підключіть репозиторій (GitHub/GitLab) з цим проєктом.
2. Render автоматично побачить `render.yaml` і запропонує створити сервіс — підтвердіть.
3. У розділі **Environment** заповніть змінну `ADMIN_PASSWORD_HASH` (див. розділ «Пароль адмінки» нижче).
   `SESSION_SECRET` згенерується автоматично.
4. Диск `omdaya-data` (1 GB) підключиться автоматично — саме там зберігатиметься `data.sqlite`,
   тому дані не губляться при передеплої.
5. Після деплою сайт буде доступний на `https://<назва-сервісу>.onrender.com` — можна підключити свій домен
   у розділі Settings → Custom Domain.

Безкоштовний план Render "засинає" після 15 хв без відвідувань і "прокидається" ~30 сек на перший запит —
для старту нормально, для серйозного трафіку варто взяти платний план.

## Варіант 2 — Railway.app

1. Створіть проєкт на [railway.app](https://railway.app), підключіть репозиторій.
2. Railway сам визначить Node.js і використає `Procfile` (`web: node src/server.js`).
3. У Variables додайте `ADMIN_PASSWORD_HASH` і `SESSION_SECRET` (див. нижче).
4. Підключіть **Volume** (постійний диск) і змонтуйте його, наприклад, у `/data`,
   а змінну `DB_PATH` виставте в `/data/data.sqlite` — без цього дані будуть губитись при кожному деплої.

## Варіант 3 — Власний VPS (повний контроль)

Підходить, якщо є сервер (Ubuntu/Debian) з SSH-доступом.

```bash
# на сервері
git clone <репозиторій> omdaya-app
cd omdaya-app
npm install
cp .env.example .env    # і заповнити реальними значеннями

# запуск через pm2, щоб сайт працював постійно і перезапускався при падінні
npm install -g pm2
pm2 start src/server.js --name omdaya-app
pm2 save
pm2 startup             # виконати команду, яку виведе ця команда — щоб pm2 стартував після перезавантаження сервера
```

Далі потрібен **Nginx** як реверс-проксі (щоб сайт віддавався на 80/443 порт з SSL), наприклад:

```nginx
server {
    listen 80;
    server_name omdaya.care www.omdaya.care;
    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

SSL — простіше за все через [Certbot](https://certbot.eff.org/) (безкоштовний Let's Encrypt).

## Пароль адмінки для продакшн (обов'язково перед публікацією!)

Не використовуйте тестовий пароль з розробки. Згенеруйте новий хеш:

```bash
node -e "console.log(require('bcryptjs').hashSync('ваш-новий-пароль', 10))"
```

Отриманий рядок (`$2b$10$...`) вставте у змінну оточення `ADMIN_PASSWORD_HASH` на хостингу.
Змінну `ADMIN_PASSWORD` (звичайний текстовий пароль) залишайте порожньою — якщо задано і хеш, і звичайний
пароль, хеш має пріоритет.

## Домен

Після вибору хостингу — прив'язати домен (якщо він вже є у заказчика) через DNS-записи (зазвичай CNAME
або A-запис на IP хостингу — точна інструкція є в документації обраного хостингу).

Не забудьте після цього заповнити поле **«Адреса сайту»** в адмінці (`/admin/settings` → розділ
«Технічне») — воно використовується для коректних посилань при пошируванні сайту в соцмережах.
