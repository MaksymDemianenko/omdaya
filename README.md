# OM DAYA — сайт благодійної організації

> **Оновлення (матеріали, чистка заглушок, SEO):**
> - Демо-записи (приклад історії, збору, сум у ₴, порожні картки команди) більше не створюються; ті, що вже були в базі й не змінювались, видаляються один раз. Реальні дані не чіпаються.
> - Блоки без даних приховуються самі: збори без посилання, суми, історії, команда, прочерки в статистиці, «уточнюється» в контактах.
> - Нове: сторінка історії `/stories/:id` з фото-галереєю; розділ «Звіти» в адмінці (показується у «Звітність»); перші дві історії та два звіти додаються один раз.
> - Згода на обробку даних у формах (RODO), `robots.txt`, `sitemap.xml`, окремі описи для кожної сторінки, адреса сайту визначається автоматично.
> - Прибрано неробочий перемикач UA/EN. Суми пожертв позначаються в €.
> - Перемикач `legal_draft` (адмінка → Налаштування → Технічне): `0` ховає позначку «чернетка» на юридичних сторінках після перевірки юристом.
> - Формат галереї (історії та звіти): кожен рядок — `шлях до фото | підпис`, напр. `/assets/stories/photo.jpg | Підпис`.

> **Оновлення (редизайн контенту):** сайт переорієнтовано на конкретну місію — підтримку дітей
> з досвідом інституційного виховання (адаптація до самостійного/безпечного життя), плюс додано
> дві нові сторінки: `/get-help` («Отримати допомогу») та `/transparency` («Звітність», з KRS/NIP/REGON
> та шаблонами фінансових і проєктних звітів). Логотип і кольори бренду не змінювались.
>
> Технічно: тексти головних сторінок (`src/db.js` → `contentDefaults`) оновлюються **один раз** при
> першому запуску після цього оновлення коду (через `content_version`), а тексти, які адмін міг уже
> вручну змінити в панелі (контакти, реквізити, соцмережі) — не чіпаються. Те саме стосується розділів
> «Напрями роботи» і FAQ: вони оновляться до нового тексту один раз, а «Команда» і «Збори» —
> не чіпаються зовсім, бо там уже є реальні дані.

Node.js-додаток: Express + EJS (сервер-рендеринг сторінок) + вбудований у сам Node.js модуль
`node:sqlite` для зберігання контенту (жодних нативних залежностей — `npm install` нічого не компілює),
з окремою адмін-панеллю для редагування текстів, історій, FAQ, команди, напрямів роботи, сум пожертв
та посилань на офіційні збори — без правок коду.

> **Важливо:** потрібен Node.js **20.19+ / 22.5+ / 23+** (десь там зʼявився вбудований `node:sqlite`).
> Перевірити свою версію: `node -v`. Якщо старіша — оновіть Node з [nodejs.org](https://nodejs.org).
> При старті в консолі буде жовте попередження `ExperimentalWarning: SQLite is an experimental feature`
> — це нормально, на роботу сайту не впливає.

## Структура проєкту

```
omdaya-app/
├── public/               статичні файли — віддаються напряму
│   ├── assets/            css, js, лого, favicon-и, og-image
│   └── site.webmanifest
├── src/
│   ├── server.js           точка входу — запуск Express-сервера
│   ├── db.js                підключення до SQLite, схема таблиць, дефолтні дані
│   ├── mailer.js            опційна відправка email через SMTP (форма контактів / підписка)
│   ├── middleware/
│   │   └── auth.js           перевірка, що адмін залогінений
│   ├── routes/
│   │   ├── pages.js           публічні сторінки сайту
│   │   └── admin.js           адмін-панель (логін + CRUD)
│   └── views/                EJS-шаблони сторінок
│       ├── partials/          header/footer/head, які повторюються на всіх сторінках
│       └── admin/             шаблони адмінки
├── scripts/
│   ├── backup-db.js           ручний / плановий бекап data.sqlite
│   └── set-admin-password.js  генерація нового пароля адмінки
├── backups/                файли бекапів (створюються скриптом, не в git)
├── data.sqlite             файл бази даних (створюється автоматично при першому запуску)
├── .env                     реальні налаштування (НЕ комітити в git, там пароль і секрети)
├── .env.example             приклад .env — що саме потрібно заповнити
└── package.json
```

## Встановлення та запуск

```bash
npm install
npm start
```

Сайт буде доступний на **http://localhost:3000**
Адмін-панель — на **http://localhost:3000/admin**

Для розробки з автоперезапуском при зміні файлів:
```bash
npm run dev
```

## Адмін-панель

Пароль для входу вже згенерований і лежить у `.env` (`ADMIN_PASSWORD_HASH`).
**Поточний пароль: `zvONNS2r`** — обов'язково збережіть його в надійному місці (наприклад, менеджері паролів)
і за бажання змініть перед публікацією сайту:

```bash
npm run set-admin-password ВашНовийПароль
```
Скрипт виведе новий `ADMIN_PASSWORD_HASH=...` — вставте його в `.env` замість старого.

У адмінці можна редагувати:
- **Налаштування** — тексти головного екрану, юридичні дані, контакти, соцмережі, банківські реквізити, цифри-досягнення, адреса сайту
- **Історії** — картки підопічних родин
- **Напрями роботи** — програми допомоги
- **Суми пожертв** — суми та опис "на що йдуть кошти" (інформаційний блок, використовується на головній і на сторінці "Підтримати")
- **Збори** — посилання на офіційні збори (siepomaga.pl, zrzutka.pl, pomagam.pl тощо) — саме вони показуються на сторінці "Підтримати" як кнопки переходу
- **FAQ** — часті запитання
- **Команда** — учасники команди фонду
- **Повідомлення** — заявки з форми на сторінці "Контакти" (тільки перегляд)
- **Розсилка** — email-адреси, залишені у формі підписки (тільки перегляд)

## Як працює "Підтримати"

Фонд працює в Польщі, тож збори ведуться через офіційні платформи (siepomaga.pl / zrzutka.pl / pomagam.pl тощо),
а не через власну платіжну інтеграцію. Сторінка `/donate` показує картки з посиланнями на ці збори —
людина натискає "Перейти до збору" і платить вже на офіційному сайті платформи, де видно суму зібраного
та прозорість використання коштів.

Додати/редагувати збори: адмінка → **Збори**. Поля: назва, платформа, посилання, опис, фото (необов'язково).

## Email-сповіщення (необов'язково)

Форма контактів і форма підписки на розсилку завжди зберігають дані в базі (видно в адмінці),
незалежно від того, чи налаштована пошта.

Якщо хочете ще й отримувати email-сповіщення про нові заявки — заповніть у `.env`:
```
SMTP_HOST=...
SMTP_PORT=587
SMTP_USER=...
SMTP_PASS=...
SMTP_FROM=...
CONTACT_TO_EMAIL=пошта-куди-надсилати@...
```
Підійде SMTP від Gmail, будь-якого поштового провайдера чи транзакційного сервісу (напр. Brevo, Mailgun).
Якщо залишити пустим — сайт просто не надсилатиме листів, все інше працює як завжди.

## Бекапи бази даних

```bash
npm run backup
```
Створює копію `data.sqlite` у папку `backups/` з датою в назві, автоматично залишає останні 30 копій.
Рекомендується поставити цю команду в планувальник (Task Scheduler на Windows або cron на Linux) — напр. раз на добу.

## Юридичні документи

На сайті вже є чернетки трьох сторінок: `/privacy` (Політика приватності), `/offer` (Публічна оферта),
`/terms` (Умови використання) — типовий текст для благодійного фонду, позначений як чернетка.
**Обов'язково погодьте фінальний текст із юристом перед публікацією** — файли лежать у
`src/views/privacy.ejs`, `offer.ejs`, `terms.ejs`.

## Favicon та зображення для соцмереж

Іконка сайту (favicon) та картинка для прев'ю в соцмережах (og:image) вже згенеровані з лого фонду —
лежать у `public/favicon.ico` та `public/assets/og-image.jpg`. Якщо лого зміниться — просто замініть ці файли
на нові тих самих розмірів (favicon: 16/32/48/180/192/512px, og-image: 1200×630px).

## Технології

- [Express 5](https://expressjs.com/) — веб-сервер
- [EJS](https://ejs.co/) — шаблони сторінок (рендеряться на сервері, без збірки фронтенду)
- [`node:sqlite`](https://nodejs.org/api/sqlite.html) — вбудована в Node.js база даних, без нативної компіляції
- [express-session](https://github.com/expressjs/session) + [bcryptjs](https://github.com/dcodeIO/bcrypt.js) — авторизація в адмінці
- [nodemailer](https://nodemailer.com/) — опційна відправка email-сповіщень

## Якщо щось не запускається

- **`node -v` показує версію нижче 20.19** — оновіть Node.js з nodejs.org, `node:sqlite` в старіших версіях відсутній.
- **Порт 3000 зайнятий** — змініть `PORT` у `.env`.
- **Забув пароль адмінки** — згенеруйте новий: `npm run set-admin-password НовийПароль`, вставте хеш у `.env`.
